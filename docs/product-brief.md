# Stillroom — product brief

## Product intent

Stillroom is a web based exam practice platform built with React, Vite, and TypeScript. Its core job is to turn structured exam data into a calm, interactive study session. Exam data may be written by a person or generated by an LLM. The app should not depend on any particular subject, course, school, or exam provider.

The primary user is the owner practicing advanced linear algebra, including difficult questions that expose gaps in understanding. The content model and interface must remain broad enough for any subject and for multilingual question text.

## LLM authoring workflow

The start page should help a user prepare a useful prompt for an LLM. The prompt builder asks for the exam subject or topic, learning goal, difficulty, exam mode, preferred question style, and an exact count for each selected question type: multiple choice, short answer, free response, and proof. The total question count updates from these per-type counts, and the prompt requires the LLM to return exactly that distribution. Every generated question must include a `type` field so the runner can show its matching answer layout. The builder also asks how many options each multiple-choice item should have. Its output updates as the user edits these fields and can be copied with one action.

The generated instruction must request exactly one clean JSON object: no prose before or after it, no Markdown fences, and no unrequested keys. It must include the exact application schema, require unique question and choice IDs, require each answer ID to match a choice, and request plausible distractors, one unambiguous correct answer, a worked explanation, and a keyed explanation for every incorrect choice. Mathematical content must use delimited LaTeX so it renders in the app. For washback exams, it requests progressively revealing hint levels with explicit point costs. The prompt builder includes an option to hide choices until the learner records a free-form result. The user copies the LLM's response and pastes it into the exam importer; the app finds the exam object even if the LLM adds surrounding prose, Markdown fences, or a common wrapper such as `{"exam": ...}`. It then trims unknown properties from the exam, question, choice, and hint objects while validating the fields the app needs. Extra material is tolerated, but missing or malformed required exam data still produces a clear error.

Users can also skip prompt generation and import a JSON file or paste JSON written elsewhere. Exam content and progress remain in the browser; no lesson database, account service, or external content API is required for the core workflow.

## Exam modes

### Washback

- Present one question at a time and unlock questions in order.
- Let the user select an answer, then explicitly commit it or mark that they do not know.
- Lock a committed answer and reveal whether it was correct plus its explanation.
- Optionally hide all multiple-choice options until the learner records a written result, then reveal the options for comparison.
- Show the correct option or model solution first, followed by the worked reasoning and per-distractor explanations or written grading rubric. Mathematical answers and explanations render LaTeX. Written responses are compared by the learner against the rubric and self-marked.
- Provide optional, sequential hint levels. Each revealed hint subtracts its declared cost from that question's available points.
- Track progress, elapsed time, score, and completion. Preserve an in-progress session locally so it can be resumed.

### Feedback

- Let the user move among questions and change answers before finishing.
- Show feedback and explanation after a choice.
- Present a final summary when the user finishes.

## Exam data contract

The root exam object includes `title`, optional `subtitle` and `subject`, `mode` (`washback` or `feedback`), optional `pointsPerQuestion`, optional `hideOptionsUntilWork`, and a nonempty `questions` array. Every question has a unique `id`, `type`, and `prompt`. Supported types are `multiple-choice`, `short-answer`, `free-response`, and `proof`. Multiple-choice items include at least two `{id, text}` choices, an `answer` matching a choice ID, and an `explanation`; generated exams also include `choiceExplanations`, keyed by every incorrect choice ID. Written items have no choices and include `expectedAnswer` (the model solution) and `rubric` (grading criteria); optional `explanation` can add context. The learner writes and submits a response, then compares it with the model answer and rubric and self-marks it. The app does not automatically grade written work or contact an instructor. Hints have `label`, `text`, and numeric `cost`. Questions may also include `topic`, `difficulty` (`gentle`, `deep`, or `brutal`), and their own `points` value.

Question text, choices, hints, and explanations support Markdown and LaTeX written as `$inline math$` or `$$display math$$`. See the example in [README.md](../README.md).

## Study experience and visual direction

The product should feel focused, quiet, and comfortable for long study sessions. Keep navigation and decoration restrained, make question text the visual center, use a readable display face with a clean interface font, and provide an optional focus mode. The interface should work on desktop and mobile, use accessible controls, and respect reduced-motion settings.

The supplied exam page at `https://azmoon.konkurcomputer.ir/azmoon/run` was opened in the connected Chrome/Playwright tab as a layout reference. Useful patterns included a question canvas, compact question palette, timer, progress state, and a clear finish action. The platform is independent of that site's branding and subject matter; the supplied page's personal account and attempt data are not product content.

## Current implementation scope

- Local React/Vite/TypeScript application.
- Demo advanced linear algebra exam to make the experience usable on first launch.
- Washback and feedback session flows.
- JSON file and paste import with validation.
- LLM prompt builder with live preview and copy action.
- Markdown and KaTeX rendering for mathematical questions.
- Local autosave, timer, focus mode, scoring, and result summary.

## Product boundaries

The platform presents the supplied exam data and provides interaction, scoring, feedback, and engagement features. It does not generate or verify exam content itself; LLM generation happens in the user's chosen LLM. It should not introduce platform-specific lesson catalogs, a distracting social feed, or a dependency on the referenced exam site's backend.

## Question explanations

Each question offers an Explain more prompt tailored to its imported question JSON and an optional learner request. The prompt specifies Markdown/LaTeX and a versioned JSON response protocol (stillroom.explanation.v1) with Markdown blocks and optional declarative 2D SVG diagrams. Learners paste the LLM response into the modal. The app renders only supported Markdown and an allowlist of SVG shapes/attributes; it does not execute generated code. Explanations are stored by question ID in the autosaved active run in browser local storage, so they remain available when navigating questions, leaving and resuming, or reloading the app on the same device.

## Exams library

Exams keeps each practice attempt in IndexedDB, including answers, proof grading, progress and attached explanations. Resume unfinished attempts or review a completed attempt and practice it again. The previous active session migrates on first load. History belongs to the current browser profile and can be lost if site data is cleared.
Download a library backup from Exams and restore it in another profile. Restore adds missing attempts and keeps existing ones.
